# Migraciones del kit — procedimiento

Un proyecto ya inicializado (`.docs/sdd/` existe) no se re-inicializa: se migra. Cada fichero `vX.Y.Z.md` de esta carpeta recoge los cambios estructurales que esa versión del kit pide al proyecto, como pasos-predicado que se pueden verificar.

1. **Desde dónde**: lee `.docs/sdd/sdd-kit.json`. Si no existe, el proyecto es anterior a v0.2.0: se aplican todas.
2. **Hasta dónde**: la mayor versión que tenga fichero en esta carpeta. **Nunca** `plugin.json`, el changelog ni el marcador del propio kit: el canal `npx skills add` no los instala, y durante una release el manifest va por detrás de las migraciones. Esta carpeta es la verdad: si existe `v0.6.0.md`, se aplica v0.6.0. Orden: por nombre de fichero (válido mientras las versiones sean de un dígito por segmento; cuando exista `v0.10.0`, ordenar por SemVer).
3. **Cómo**: aplica cada fichero en orden, paso a paso. Cada paso empieza por un predicado: si no se cumple, se salta y se dice. Los pasos **sin** marca de gate (sustituciones de texto, renombrar una tabla) se ejecutan sin preguntar: son reversibles y el dev-lead los revisa en el diff. Solo los pasos marcados **gate** se presentan al dev-lead antes de ejecutarse (un rename masivo, un borrado, un diff de `estimation-log.md`); si el dev-lead no está, se dejan como pendientes explícitos, nunca se hacen por su cuenta — ni ejecutados, ni staged «para que lo revise»: pendiente significa sin tocar, con el comando exacto listado en el informe.
4. **Qué NO es migrar**: regenerar documentos de anclaje, volcar `funcional/`, trocear `funcional.md`, tocar specs o walkthroughs históricos, borrar scripts del proyecto que no sean del kit.
5. **Al terminar**: escribe `.docs/sdd/sdd-kit.json` con la versión aplicada, el canal (`plugin` si el kit llegó por `/plugin install`, `cli` si por `npx skills add`) y la fecha; ejecuta la sección «Verificación» de cada fichero aplicado; un commit por versión migrada (`chore(sdd): migrar al kit vX.Y.Z`) cuando sus gates estén resueltos — si quedan gates pendientes, deja el working tree con los cambios aplicados y la lista de pendientes en el informe, sin commit ni marcador.
