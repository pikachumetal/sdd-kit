# Migración a v1.2.0 — modo de ids y claves de control

Aplica a cualquier proyecto cuyo `.docs/sdd/sdd-kit.json` le falte el campo `ids`, `control.profile` o un
bloque `merge` completo. Un proyecto inicializado ya con el kit v1.2.0 o posterior recibe estos campos en
su propia entrevista de init y aquí no encontrará nada que hacer: cada paso se salta por predicado.

1. **Modo de numeración.** Si `.docs/sdd/sdd-kit.json` no tiene campo `ids`: **gate** — presentar al dev-lead los dos modos, ids del gestor de tickets (`tracker`) o secuencia propia del proyecto (`sequence`), y escribir su respuesta en `ids.mode`. Si el dev-lead no está, el paso queda **pendiente explícito**: no se inventa una respuesta, el proyecto sigue funcionando en `tracker` mientras tanto (ausencia de campo `ids` = `tracker`, Art. IV), y el informe anota cómo reanudarlo: reinvocar `sdd-init-brownfield` sobre este proyecto.
2. **Claves de control.** Si falta `control.profile` o un bloque `merge` completo: **gate** único —
   presentar al dev-lead los perfiles (`pair`, `delegate`, `unattended`; recomendado `delegate`) y la
   política de merge a `develop`, y escribir en `sdd-kit.json` solo lo que responde (perfil suelto, merge
   suelto o los dos). Lo que ya estaba no se pregunta. Si el dev-lead no está, el paso queda **pendiente
   explícito**: el proyecto sigue funcionando con `control.profile: "delegate"` (el default) y con el
   paso 10 del cierre de task preguntando la política de merge, como hoy; el informe anota cómo
   reanudarlo. Gates y claves: [control-profiles.md](../../../sdd-start-task/references/control-profiles.md).
3. **Marcador.** Escribir `.docs/sdd/sdd-kit.json`: `{ "version": "1.2.0", "channel": "plugin" | "cli", "updated": "<hoy>", "ids": { "mode": "tracker" | "sequence" } }`, añadiendo `"control": { "profile": "<respondido>" }`
   y/o `"merge": { "into": "<respondido>", "noFf": <respondido>, "removeWorktree": <respondido> }` solo si
   el paso 2 obtuvo esa respuesta.

No se toca `specs/`, `changelog.md`, `roadmap.md` ni `releases/`: describen lo que ya se entregó y reescribirlos falsearía el histórico.

## Verificación

- `(Get-Content .docs/sdd/sdd-kit.json -Raw | ConvertFrom-Json).ids.mode` devuelve `tracker` o `sequence`.
- `(Get-Content .docs/sdd/sdd-kit.json -Raw | ConvertFrom-Json).control.profile` devuelve un perfil válido
  (`pair`, `delegate` o `unattended`), o el informe lo lista como pendiente.
- `.docs/sdd/sdd-kit.json` existe con `"version": "1.2.0"`.
- `git log --diff-filter=M --name-only -1 -- .docs/sdd/changelog.md .docs/sdd/roadmap.md` no muestra esta migración: ninguno de los dos se tocó.
