# Migración a v2.0.0 — capacidades sin historial

Aplica a cualquier proyecto con `.docs/sdd/capabilities/` cuyas capacidades tengan la sección `## Historial`. Desde la v2.0.0 una capacidad solo lleva sus requisitos y sus reglas: quién cambió qué lo dicen git y el bloque «Capacidades» de cada spec o `patch.md`. Un proyecto inicializado ya con el kit v2.0.0 o posterior no tiene historial en sus capacidades: el paso se salta por predicado.

1. **Historial de las capacidades.** Si alguna `.docs/sdd/capabilities/*.md` tiene una sección `## Historial`: se borra la sección entera, desde su título hasta la siguiente sección `##` o el final del fichero, y nada más. Sin gate: el historial queda en git y el dev-lead lo ve en el diff. Si no existe `capabilities/`, o ninguna capacidad tiene historial, el paso se salta y lo dice.
2. **Marcador.** Escribir `.docs/sdd/sdd-kit.json` con `"version": "2.0.0"`, el canal y la fecha, sin tocar las demás claves.

**Escribe**: `sdd-kit.json` → `version`, `channel`, `updated`. Además borra el historial de cada capacidad (paso 1).

## Verificación

- `pwsh -NoProfile -File "<Base directory de sdd-templates>/scripts/Test-Capabilities.ps1" -Path .docs/sdd` escribe `Capacidades válidas: <n>` o `Sin capacidades que validar`. Si falla por otra cosa que el historial —un bloque `**Reglas de la capacidad**` pegado de un delta, un requisito sin escenario—, el informe lo lista como pendiente del dev-lead, sin tocarlo.
- `Select-String -Path .docs/sdd/capabilities/*.md -Pattern '^## Historial'` no devuelve nada.
- `.docs/sdd/sdd-kit.json` existe con `"version": "2.0.0"`.
