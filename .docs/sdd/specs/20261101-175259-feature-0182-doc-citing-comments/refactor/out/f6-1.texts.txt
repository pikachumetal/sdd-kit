#### Important (Should Fix)
1. **`src/app.js:51`: the comment `// Task 4: validar antes de guardar` cites a plan document.**
   - "Task 4" goes stale as soon as the plan is renumbered or archived. Nothing in the repo explains what Task 4 is.
   - The rest of the comment only repeats what line 52 does (validate the room, then return).
   - Delete it. If a reason is needed, state it directly, for example why the room is validated at all.

2. **`src/app.js:52-54`: `saveRefund` doesn't save anything, and its return type is inconsistent.**
   - The function name and the commit message say "guardar la devolución". The function only returns an object. It writes no booking, refund or state.
   - It returns the string `'sala no válida'` on failure and an object on success. A caller can't tell an error from a result without checking the type, and any caller that treats the string as data will break.
   - Throw an error or return `{ ok, error }`. If persistence belongs to a later task, the spec should say so and the function name should reflect it.

3. **`src/app.js:54`: `iban.replaceAll(' ', '')` has no input checks.**
   - `iban` that is `undefined`, `null` or not a string throws a `TypeError`.
   - Only plain spaces are stripped. Tabs and non-breaking spaces stay in.
   - Nothing checks that the IBAN is valid, or that it isn't empty after stripping.
   - A caller passing an empty or missing IBAN gets an exception or an empty IBAN stored as valid. Add a type check and return a clear error.
