### Strengths
- The change is small and easy to read. `CANCEL_REASONS` is a single constant, and the list in the error message comes from `CANCEL_REASONS.join(', ')`, so the list of reasons lives in one place (DRY).

### Issues

#### Minor (Nice to Have)
1. `test/cancel.test.js:1-25`. Commit `b72cc18` converted the whole file from CRLF to LF, so the package diff shows the file as fully rewritten (lines 82-117). With `--ignore-cr-at-eol` the real change is about 20 lines. This hides what actually changed in review and in `git blame`, and it is not a formatter requirement. To fix it, either restore the original line endings or confirm that the LF conversion was intentional (`.gitattributes` or the editor). I found no `.gitattributes` or `.editorconfig`.
2. `test/cancel.test.js:11-25`. Possible «tests should be independent» (Clean Code, F.I.R.S.T.). The tests share the module-level `bookings` state and only pass in file order. Here, the third test cancels Norte lun, and the fourth, `canceladas`, depends on that. The test «cancelar sin reserva» passes only because Sur mar never exists. Running a test alone, for example with `--test-name-pattern`, or reordering them breaks `canceladas`. The fix is to make that test cancel its own booking first, or to export a reset function for the state. This is mild, because the spec's GIVEN already assumes a cancellation made earlier.
3. `src/app.js:37-40`. Possible «error handling separate from logic» (Clean Code). `optionValue` returns `params[index + 1]` without checking that it is not another flag. Today this is harmless, because anything not in the list is rejected. It would become a real problem if `optionValue` were reused for a flag whose value is free text. It is also not stated that `--motivo` must come after the two positional arguments: `cancelar --motivo otro Norte lun` reads `params[0]` and `params[1]` as the room and day and gives «sin reserva --motivo otro». I'm not asking for a change, because the spec fixes the syntax as `cancelar <sala> <día> --motivo <motivo>`.
4. `src/app.js:59-64`. `cancelledBookings()` returns an empty string when nothing is cancelled, so `console.log` prints a blank line. A reasonable user would expect a message such as «sin canceladas», in line with «sin reserva…». The spec doesn't cover it, so this is a suggestion.
5. `src/app.js:66-74`. Possible «long if-chain / switch smell» (Refactoring). The dispatch in `run` adds one more `if` per command. At 6 branches it is still fine, and a command table would be premature.
