### Strengths
- The change is small and easy to read. `reasons` is a single source of truth, and the same list builds the error message and does the validation.
- `reasonOf` is separate from `cancelBooking`, so argument parsing stays out of the domain function.
- All user-facing text is in Spanish, as the constraint requires. The error message lists the valid reasons, which helps the person typing the command.
- Validating the reason before looking up the booking means an invalid reason never mutates state.
- Voided bookings are excluded from the cancelled list, because `cancelledList` filters on `status === 'cancelled'` only.

### Issues

#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **`test/cancel.test.js:12-14`: the `canceladas` test depends on state left by another test.**
   - It expects `'Norte lun — sala ocupada'`, which exists only because the first test already cancelled that booking in the module-level `bookings` array.
   - Run alone (`--test-name-pattern`) or in a different order, it returns an empty string and fails.
   - Fix: make the test independent. Either cancel the booking inside the test before asserting, or expose a way to reset the state. For example, export a `resetBookings` function, or make `run` take the store.

2. **`test/cancel.test.js:7-10`: the "no reservation" path lost its test.**
   - The old test `cancelar sin reserva lo dice` was repurposed into the invalid-reason test.
   - No test now covers `cancelBooking` returning `sin reserva Sur mar` when the reason is valid.
   - There is also no test for omitting `--motivo` (`reasonOf` returns `undefined`), and none for `canceladas` with nothing cancelled.
   - Fix: keep the old test with a valid reason added, `run('cancelar', ['Sur','mar','--motivo','otro'])`. Add a test for the missing flag.

#### Minor (Nice to Have)
1. **`src/app.js:56-58`: possible silent empty output.**
   - With no cancelled bookings, `canceladas` returns `''`, so `console.log` prints a blank line.
   - A person using the CLI would expect a message such as `sin canceladas`.
   - Same file, `reasonOf`: it is positional-fragile. `cancelar Norte --motivo otro lun` takes `--motivo` as the day, and the output is the confusing `sin reserva Norte --motivo`.
   - Fix: filter the flag and its value out of the positional arguments, or document that the flag goes last.

2. **`src/app.js:40`: a missing `--motivo` reports `motivo no válido: ...`.**
   - "Not valid" is slightly misleading when the person gave no reason at all. `falta el motivo` or `motivo obligatorio: ...` would be clearer.

3. **`test/cancel.test.js:8`: the invalid-reason test does not check that nothing changed.**
   - It only asserts the message, not that the booking was left untouched.
   - The lookup runs after validation, so this is low risk today, but a regression there would go unnoticed.
