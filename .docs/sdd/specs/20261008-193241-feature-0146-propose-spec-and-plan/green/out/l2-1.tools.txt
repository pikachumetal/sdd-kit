=== RESULTADO (13 turnos, 0.1353072 $)
Here's how a March export travels, using the member who runs the export for March 2026. The data holds five bookings, and the export keeps three of them.

1. **You ask.** You type the export command from the terminal and give it the month, `2026-03`. The command only reads the month and hands it to the export.
2. **The bookings are loaded.** The tool reads the whole list of bookings the coworking has saved, for every month. In the example that's the five bookings: Norte on 2 March 10:00–12:00, Sur on 5 March 16:00–17:00, Norte on 12 March 09:00–10:00 (cancelled), Norte on 19 March 12:00–13:30, and Sur on 1 April 10:00–11:00.
3. **The list is narrowed down.** The tool keeps only bookings whose day falls in March and drops cancelled ones. The 12 March booking is gone because it was cancelled, and the 1 April one is gone because it isn't March. The remaining three are sorted by day and time slot, so they come out in calendar order.
4. **Each booking becomes a calendar event.** Each one gets a title, "Sala Norte" or "Sala Sur" (the room), plus a start and an end. The tool treats the time slots as coworking time, two hours ahead of the universal reference clock calendars use. So the 2 March 10:00 booking is written as 08:00, and its end as 10:00. The three events are wrapped in a calendar header and footer.
5. **The file is saved.** The tool creates an exports folder if it doesn't exist and writes the March export file there. It prints where it saved the file, and that's the answer you see in the terminal.

After that, you open the file or import it into Google Calendar or Outlook, and the three bookings appear on your calendar. Nothing stays connected afterwards. If a booking changes tomorrow, you export again.

Reading the code turned up two things in step 4:
- **Missing marker:** The converted times lack the marker that says "this is the reference clock". A calendar may read the 08:00 as 08:00 on your own clock, which would show the 2 March booking two hours early.
- **Fixed offset:** The two-hour offset is fixed all year. If the coworking's clock moves an hour in winter, those exports would be off by one hour.

I haven't run the tool to confirm either of these.
