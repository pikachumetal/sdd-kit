## Users

- **Socio del coworking**: reserva salas y se lleva sus reservas a su calendario.
- **Responsable del coworking**: mantiene la herramienta.

## Product Purpose

Reservar las dos salas de reuniones del coworking desde la terminal y llevarse las reservas de un mes al calendario de cada uno (Google Calendar, Outlook) con un fichero que se importa.

## Capabilities and Constraints

- **Es**: reservar, cancelar y exportar las reservas de un mes.
- **No es**: un calendario compartido ni una sincronización en vivo.

=== RESULTADO (5 turnos, 0.12375340000000001 $)
Here is how an export travels, using March 2026 as the example.

**What you start with.** You type `exportar --mes 2026-03` in the terminal. The saved reservas for March are:
- Norte, 2 March, 10:00–12:00
- Sur, 5 March, 16:00–17:00
- Norte, 12 March, 09:00–10:00 (cancelled)
- Norte, 19 March, 12:00–13:30
- Sur, 1 April (a different month)

**The steps**

1. **The command reads your request.** It sees "exportar" and takes the text after `--mes`, which is `2026-03`. It hands that month to the exportación machinery.
2. **All reservas are loaded.** The tool reads the single file where every reserva is kept. The example gives all five reservas, from both salas and both months.
3. **The list is narrowed.** Only reservas whose day starts with `2026-03` are kept, and cancelled ones are dropped. The Sur reserva on 1 April goes, and so does the cancelled 12 March one. What remains is sorted by day and then by franja: Norte 2 March, Sur 5 March, Norte 19 March.
4. **Each reserva becomes a calendar entry.** Each one gets a title ("Sala Norte"), a start and an end. The franja is written in coworking time, which the tool treats as always two hours ahead of UTC. UTC is the universal clock that calendars expect. So Norte on 2 March, 10:00–12:00, is written as 08:00–10:00 UTC. Your calendar converts it back to your own timezone when you import it.
5. **The entries are wrapped into one calendar file.** A header and footer go around the three entries, which makes a single `.ics` file. That is the format Google Calendar and Outlook import.
6. **The file is saved.** The tool creates the exports folder if it's missing and writes the file there, named after the month. The command prints that location in the terminal.

**After the steps (outside the tool).** You open Google Calendar or Outlook, import that file, and the three reservas appear on 2, 5 and 19 March. Nothing stays linked afterwards. If a reserva changes later, you export again and re-import, because this is a one-off file and not a live sync.

**Two things I noticed while reading the code**
- The two-hours-ahead offset is fixed. It doesn't change with daylight saving, so reservas in months where the coworking clock shifts could land an hour off.
- The start and end times are written without the marker that says "this is UTC". A calendar may therefore read 08:00 as its own local 08:00 instead of converting it. I haven't run an import to confirm this.

The feature that exports only one sala (`--sala`) is still a draft. Today every export contains both salas.
