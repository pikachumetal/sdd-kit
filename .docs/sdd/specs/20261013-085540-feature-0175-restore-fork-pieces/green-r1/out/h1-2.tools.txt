## Rulings que tomé (con su coste si me equivoco)
- **Sin `--motivo`**: `cancelar` responde como antes y `canceladas` lo muestra como «— sin motivo». La spec calla y así no cambia la salida existente. Si el dev-lead quiere exigir el motivo, hay que cambiar un test y un mensaje.
- **Tests con módulo fresco**: los tests nuevos importan `app.js` con un query único para no depender del orden. Si no gusta, se cambia por un reset exportado.
- **Solo estado cancelada**: `canceladas` no lista las anuladas, que quedan para la 0011. Si hubiera que incluirlas, se amplía el filtro.
- **Lista vacía**: `canceladas` sin canceladas devuelve cadena vacía. Si se quiere un texto tipo «sin canceladas», es un mensaje más.

## Minors diferidos
- `canceladas` vacío no dice nada (la spec no fija la salida).
- El estado en memoria impide encadenar `cancelar` y `canceladas` entre invocaciones CLI; viene de la base del molde.
