Porque `cancelar` no cancela nada. Solo devuelve un texto, y `libres` no distingue días.

Esto es lo que dice el código en `src/app.js`:

- **`cancelar` no toca las reservas.** Devuelve `` `cancelada ${params[0]} ${params[1]}` `` y nada más. El array `bookings` queda intacto, así que Norte `10:00-12:00` sigue reservada.
- **`libres` solo mira la franja.** `freeRooms(slot)` filtra por `b.room === room && b.slot === slot` y no recibe día. La reserva `{ room: 'Norte', day: 'lun', slot: '10:00-12:00' }` bloquea Norte en esa franja para cualquier día.
- **`cancelar` recibe `(día, hora)` y no `(sala, día, franja)`.** No hay forma de decir qué sala se cancela.
- **El estado no persiste entre ejecuciones.** `bookings` es un array en memoria con una reserva fija. Cada invocación de la CLI arranca de nuevo con Norte reservada el lunes, aunque `cancelar` sí la borrara.

También hay una discrepancia con la documentación. `patch-0007-cancel/patch.md` dice «Causa raíz: comparación solo por hora. Fix y test de regresión. Verificado», pero el código no tiene ningún fix. El test `cancelar respeta el día` solo comprueba que el string de salida contiene `mar 10:00`, así que no habría detectado el problema. La spec `task-0006-free` está vacía salvo `status: done`, por lo que no hay un comportamiento documentado de `libres` con el que contrastar.
