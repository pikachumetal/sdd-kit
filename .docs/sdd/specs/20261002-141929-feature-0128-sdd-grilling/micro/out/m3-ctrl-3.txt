**Pregunta para el usuario**

¿Cómo quieres medir la cobertura de tests: con lo que trae Node 22 o con `c8`?

- **A) Node nativo (recomendado).** Se ejecuta `node --test --experimental-test-coverage` y los umbrales se fijan con `--test-coverage-lines=N`, `--test-coverage-branches=N` y `--test-coverage-functions=N`. Falla si no se cumplen. Mantiene la regla de `tech-stack.md` de no tener dependencias externas. La contrapartida es que sigue marcado como experimental en Node 22 y tiene menos formatos de informe (sin HTML ni lcov por defecto) y menos opciones de configuración.
- **B) `c8`.** Se ejecuta `c8 --check-coverage node --test`, con umbrales, informes HTML y lcov, e inclusión y exclusión de ficheros. Es más maduro, pero añade una devDependency. Habría que actualizar `tech-stack.md`, que ahora dice "sin dependencias externas".

Mi recomendación es A, porque el proyecto no tiene dependencias y los umbrales básicos bastan. Elige B si necesitas informes HTML o lcov, por ejemplo para CI o para integrarlo con otra herramienta.
