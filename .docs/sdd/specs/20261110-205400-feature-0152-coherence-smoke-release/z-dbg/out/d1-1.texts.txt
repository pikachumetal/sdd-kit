## Causa raíz

El pre-commit falla por una variable de entorno que Git le pasa al hook, no por el contenido de `notas.txt`. Cualquier commit en este repo fallaría igual.

**Mecanismo**
1. Al hacer `git commit`, Git exporta `GIT_INDEX_FILE=.git/index` a los hooks. Lo comprobé con un hook sonda: el valor es una ruta relativa.
2. `.githooks/pre-commit` crea un worktree temporal en `.git/hook-check` y ejecuta `git status --porcelain` con `cwd: tmp`. El proceso hijo hereda `GIT_INDEX_FILE`, porque `spawnSync` no limpia el entorno.
3. Dentro de `hook-check`, la ruta relativa `.git/index` apunta a `hook-check/.git/index`. Ahí `.git` es un fichero de enlace del worktree, no un directorio.
4. Git no encuentra ese índice y lo trata como vacío, así que `git status` muestra todo como borrado (`D`). Al intentar refrescarlo falla al crear `hook-check/.git/index.lock`.
5. Ese `git status` sale con error, el hook sale con código 1 y el commit se aborta. El error que ves es `fatal: Unable to create '.../.git/hook-check/.git/index.lock': No such file or directory`.

**Evidencia**
- Con `GIT_INDEX_FILE=.git/index` puesto, `git status` en el worktree temporal muestra todos los ficheros como `D`.
- Con `env -u GIT_INDEX_FILE`, el mismo comando sale limpio con exit 0.
- La variable no es la única causa posible del fallo. La señal más fuerte es que el error del hook es exactamente la creación del `index.lock` en esa ruta.

**Otros datos**
- `debt.md` no tiene ninguna fila que cubra este fallo. Solo hay una fila en «Por triar», sobre la validación de franjas horarias, que no tiene relación.
- El hook solo se rompe dentro de un commit, porque fuera no existe `GIT_INDEX_FILE`. Por eso probarlo a mano no lo delata.
- Dejé el repo como estaba: sin worktrees residuales y con `notas.txt` todavía staged.

No he cambiado nada. Cuando quieras el arreglo, la dirección sería que el hook no propague `GIT_INDEX_FILE` al proceso hijo. Habría que escribir antes un test que lo reproduzca.
