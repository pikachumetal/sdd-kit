Here is how a March export travels. I read the code first, so each step below matches it.

**Example:** a member asks for the export of March 2026. The command is `exportar --mes 2026-03`. The bookings data has four March reservations:
- Norte, 2 March, 10:00–12:00, confirmed.
- Sur, 5 March, 16:00–17:00, confirmed.
- Norte, 12 March, 09:00–10:00, cancelled.
- Norte, 19 March, 12:00–13:30, confirmed.

It also has one April reservation.

1. **The command line** reads the word `exportar` and the month `2026-03`. It passes the month on and prints whatever comes back.
2. **The reservation store** reads the whole list of reservations from the data file. It does not filter anything. All five reservations go on.
3. **The filter** keeps the reservations whose day starts with `2026-03`. The April one is dropped. It also drops cancelled reservations, so the 12 March one is dropped. Three remain. It sorts them by day, then by time slot: 2 March, 5 March, 19 March.
4. **The calendar builder** turns each reservation into one calendar event, titled "Sala Norte" or "Sala Sur".
   - The time slot is in coworking time, which is two hours ahead of UTC. The builder converts it, so 10:00 on 2 March becomes 08:00.
   - The three events go between a calendar header and footer, as one block of text.
5. **The writer** creates the export folder if it is missing. It saves the text there as one file named after the month, then returns the file's location.
6. **The command line** prints that location. This is the last thing the code does.

After the steps, outside the code: the member opens that file in Google Calendar or Outlook and imports it. The three reservations appear in their calendar. Nothing stays in sync. If a reservation changes later, the member has to export again.

**Two things I noticed while reading:**
- The converted times have no marker saying they are UTC. A calendar may read 08:00 as local time, not as 10:00 coworking time. I have not run an import to check.
- The month is not validated. If the member types a month with no reservations, or forgets `--mes`, the command still runs. A month with no reservations gives a valid file with no events.

**Where to look**
- Step 1: `src/cli.js`
- Steps 1–5 in order: `src/export/index.js`
- Step 2: `src/bookings/repository.js` and `data/bookings.json`
- Step 3: `src/export/filter.js`
- Step 4: `src/export/ics.js`
- Step 5 and the file the member gets: `src/export/writer.js` (saved as `exports/2026-03.ics`)
