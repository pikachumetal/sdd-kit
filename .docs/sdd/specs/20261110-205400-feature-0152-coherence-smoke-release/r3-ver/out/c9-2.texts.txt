## New Breakage in the Fix Diff

- **Minor, `src/app.js:37` (spec):** «las 20 últimas cancelaciones» in decision 4 means the 20 most recent cancellations. The code takes the last 20 in the `bookings` array, which is creation order. Example: a booking created early and cancelled later sits near the front of the array. Once there are more than 20 cancellations, it falls into «… y N más» while cancellations made before it are still shown. The thread admits this in its own note, but the spec has no amendment for it («Enmiendas: (ninguna)»). Fix options:
  - record when each booking was cancelled (a counter set in `cancelBooking`) and sort by it before `slice(-20)`, or
  - add an amendment to the spec saying «últimas» means booking order, for the dev-lead to approve.
- **Minor, `test/final-review.test.js:9-16`, the tests depend on their order:** the second test expects `… y 5 más`. That 5 only works because the first test already cancelled Norte lun, giving 1 + 24 = 25 cancellations. Run on its own (for example with `--test-name-pattern`), the line would be `… y 4 más` and the test would fail. Fix: either compute the expected count from the current state of `bookings`, or set up all the data inside the test.
