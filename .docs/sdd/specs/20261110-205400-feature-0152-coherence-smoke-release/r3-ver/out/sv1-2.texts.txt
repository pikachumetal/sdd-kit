### Issues

#### Critical (Must Fix)

1. **The recommendation rests on an objective nobody measured.** `research.md` §4: «comprar el quiosco · Por qué: aguanta (O1) y el consumo de memoria con 1.000 reservas es bajo (O2)».
   - **What's wrong:** O2 is «no medido / no dio tiempo» in the table of that same file. O1 doesn't hold either (see issue 2).
   - **The rule it breaks:** the research template's §4 allows only measured rows, and never a `no medido` counted as met.
   - **Why it matters:** this spike exists to answer «si compramos el quiosco este trimestre». As written, it recommends a purchase that none of the four objectives supports.
   - **How to fix:** cite only measured rows. With nothing met, the honest answer is «no seguir» or «medir O2/O4 primero».
   - **Gap:** `contradicts`. **Source:** the spec's «Decisión que desbloquea», plus objectives O1 and O2.

2. **O1 is reported as `cumple`, but the evidence shows it fell short.**
   - **Where:** the O1 row of the table in `research.md` §2, compared with `evidence/o1.txt`.
   - **What's wrong:** O1 requires ≥ 5 min without errors. The evidence says «libres en bucle, 2 min 30 s, 0 errores».
   - **How to fix:** the template's state for this is «no cumple tal como se definió». The other option is to run the full 5 minutes again.
   - **Gap:** `contradicts`. **Source:** objective O1.

#### Important (Should Fix)

3. **A spike that shouldn't change code changes `src/app.js`.**
   - **What's wrong:** `src/app.js:40` adds `export const kioskMode = true;`. Nothing reads it, and no test or verification pins it. On top of that, the whole file was rewritten from CRLF to LF line endings: 79 lines of diff for 1 real change.
   - **What it contradicts:** the plan says «Eje Arquitectura: no — no cambia código». The spec lists «Capacidades: Ninguna». The template's §5 says «el spike no deja código de producción».
   - **Why it matters:** it adds kiosk API surface before anyone has decided to buy the kiosk.
   - **How to fix:** restore `src/app.js` exactly as it was at `0ec6b2a`, line endings included.
   - **Gap:** `unrequested`. **Source:** the plan and the spec's capabilities.

4. **The dev-lead's worst-case load is only half covered.**
   - **What's wrong:** for O4 the spec records «Peor carga: 1.000 reservas activas — confirmada: «esa es la peor, sí»». The research only measured 100 reservations. It has no §3 «Aguante» section, which the template requires whenever an objective is about performance (O2 and O4 both are): ≥ 10 repetitions under the worst load.
   - **How to fix:** measure O2 and O4 with 1.000 active reservations and add §3, keeping the raw output in `evidence/`.
   - **Gap:** `partial` («decisión del dev-lead cubierta a medias: peor carga 1.000 reservas activas — la medida usa 100»). **Source:** the dev-lead decision on O4.

5. **The plan's own check for Task 1 fails.**
   - **What's wrong:** Task 1 promises evidence for «O1 a O4» and its check is «la salida en bruto existe en la carpeta de la spec». There is no raw output for O2 or O4, yet the plan doesn't record the task as failed or partial.
   - **Gap:** `partial`. **Source:** the plan, Task 1.
