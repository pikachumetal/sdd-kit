## Causa raíz

El hook `.githooks/pre-commit` falla porque, durante un commit real, git le pasa `GIT_INDEX_FILE` con una ruta **relativa** (`.git/index`). El hook hereda esa variable en sus llamadas a `git`, y la ruta se resuelve contra otro directorio.

## Cómo llegué a eso

1. **Deuda:** `.docs/sdd/steering/debt.md` no tiene ninguna fila que cubra este fallo.
2. **Ejecución a mano:** `node .githooks/pre-commit` termina con `exit=0`. `GIT_DIR` y `GIT_INDEX_FILE` no estaban definidas en mi shell.
3. **Qué hace el hook:**
   - Crea un worktree temporal en `.git/hook-check` con `git worktree add --detach … HEAD`.
   - Lanza `git status` dentro de ese worktree.
4. **Hipótesis:** en un commit real git exporta `GIT_INDEX_FILE`, y el hook no la limpia al lanzar sus subprocesos.
5. **Comprobación:** ejecuté el hook con `GIT_INDEX_FILE=.git/index-copy`, una ruta relativa como la que pone git. Falló con `Unable to create '…/.git/hook-check/.git/index-copy.lock': No such file or directory`.
   - El `.git` del worktree temporal es un archivo, no un directorio. Por eso la ruta relativa no existe allí y `git worktree add` aborta, y el hook sale con 1.
   - En mi prueba `.git/index-copy` no existía, porque el comando para copiarlo requería aprobación y no se ejecutó. El error es de creación del `.lock` en un directorio inexistente, así que no depende de que el archivo exista. Aun así no probé con un commit real.
