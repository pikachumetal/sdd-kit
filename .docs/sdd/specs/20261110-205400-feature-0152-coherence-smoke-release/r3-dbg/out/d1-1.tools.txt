El pre-commit falla porque `git commit` le pasa `GIT_INDEX_FILE` y el hook se lo hereda a un worktree temporal. Reproduje el fallo simulando esa variable. No ejecuté un `git commit` real, así que no he visto el error exacto dentro del commit.

## Causa raíz

El hook `.githooks/pre-commit` crea un worktree temporal en `.git/hook-check` y ejecuta `git status --porcelain` dentro de él. `git status` falla por culpa de `GIT_INDEX_FILE`.

1. Al lanzar un hook de commit, git exporta `GIT_INDEX_FILE=.git/index`, una ruta relativa.
2. El hook usa `spawnSync` sin pasar `env`, así que sus hijos heredan esa variable.
3. `git status` corre con `cwd: tmp`, y ahí `.git` es un fichero, no un directorio. Git intenta usar el índice en `<tmp>/.git/index` y no puede.
4. Falla con `Unable to create '.../.git/hook-check/.git/index.lock': No such file or directory`. El hook lo recoge como «el worktree temporal no responde» y sale con 1.

## Evidencia

| Ejecución | Resultado |
| --- | --- |
| `node .githooks/pre-commit` a mano | exit 0 |
| `GIT_INDEX_FILE=.git/index node .githooks/pre-commit` | exit 1, con el error de `index.lock` de arriba |
| `GIT_DIR=.git node .githooks/pre-commit` | exit 0 |

Por eso a mano pasa y solo falla dentro de `git commit`. Tampoco tiene que ver con `notas.txt`: el hook solo comprueba `HEAD` y nunca mira lo que stageas.
