### Issues

#### Critical (Must Fix)

1. **The removed email requirement still runs.** At `src/app.js:35`, `voidBooking` still calls `notifyByMail` and fills `outbox` (`:6`, `:16-18`).
   - Why it matters: the spec removes the email («el correo sobra»). Every voiding still pushes «anulada Norte lun» into the outbox.
   - Fix: delete the call, along with `notifyByMail` and `outbox` if nothing else uses them. Add a test that `outbox` stays empty after `anular … --motivo …`.
   - Gap: `contradicts`. Source: **REMOVED — Las anulaciones se avisan por correo** and the dev-lead decision «El correo de anulación desaparece».

#### Important (Should Fix)

2. **The Review Focus line has no test.** The plan names the test `pide motivo al anular` for `anular Norte lun` without `--motivo` → «falta el motivo». It isn't in the diff: `test/void.test.js` contains only `anular con motivo`.
   - Why it matters: the code does behave correctly (`:30`), but nothing pins it, so a regression would go unnoticed.
   - Fix: add `test('pide motivo al anular', () => assert.equal(run('anular', ['Norte', 'lun']), 'falta el motivo'))`. Put it before the voiding test or use another booking, because the voiding test leaves Norte/lun already voided.
   - Gap: `missing` (verification). Source: the THEN «AND `anular Norte lun` sin `--motivo` responde «falta el motivo»» and the plan's Review Focus.

3. **`anular-todas` doesn't ask for a reason.** `voidAll()` (`src/app.js:40-44`, `:52`) voids every active booking without a `--motivo`, and the reason isn't stored on the bookings it voids.
   - Why it matters: this is exactly the way in that the dev-lead said must not let a voiding through without a reason.
   - Fix: `run` passes `reasonOf(params)`, `voidAll` returns «falta el motivo» when the reason is missing and stores `booking.reason` otherwise. Add a test for each case.
   - Gap: `partial`. Source: «decisión del dev-lead cubierta a medias: Anular pide motivo en las dos vías, `anular` y `anular-todas` — la regla solo cubre `anular`; `anular-todas` sigue anulando sin motivo». The Scope also includes `anular-todas --motivo <texto>`.

4. **Voidings are saved to disk, which breaks ADR 0003.** `src/app.js:1` imports `node:fs` and `saveVoided()` (`:25-27`, `:36`) writes `data/anuladas.json`.
   - Why it matters: ADR 0003's Confirmación says «`src/` no importa `node:fs`», and the spec puts saving voidings out of scope. The test also has to create `data/` (`test/void.test.js:6`), which goes against the consequence «los tests no limpian nada». From the command line with no `data/` folder, `writeFileSync` would very likely throw ENOENT after the booking has already been marked as voided. I didn't run this.
   - Fix: remove the import, `saveVoided` and the `mkdirSync` in the test.
   - Gap: `contradicts` / `unrequested`. Source: the Confirmación of ADR 0003 and the spec's Scope («No entra»).

5. **The `libres` output changed, which nobody asked for.** At `src/app.js:47-50`, `libres` now answers «1 libres: Sur» instead of «Sur».
   - Why it matters: this changes the `availability` capability, which has no subsection in the delta. It contradicts that capability's THEN («responde «Sur»») and breaks `test/app.test.js:5-7`, which expects `'Sur'`. The phrasing «1 libres» is also grammatically wrong.

   - Gap: `unrequested`. Source: the `availability` capability, outside the delta.
