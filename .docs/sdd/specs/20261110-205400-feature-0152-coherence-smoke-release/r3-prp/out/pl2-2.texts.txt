### Strengths
- The change is small and follows the existing pattern in `src/app.js`: one function per command, with `run` dispatching.
- `reasons` is a single constant, in the required order. It drives both the validation and the error text through `reasons.join(', ')`, so the list is written once.
- `cancelBooking` checks the booking first, then the reason, and mutates only after both pass. A rejected cancel leaves the booking active, which the tests rely on.
- All three literal output texts match the brief, including the em dash with a space on each side. The `src/app.js` file in `fb04aec` has no tab characters (grepped for `\t`, no hits), so the lint constraint holds.
- There are no comments, so none repeat the code or cite documents. Names are clear (`optionValue`, `cancelledBookings`, `reasons`) and each function has one job.
- `optionValue` returns `undefined` when `--motivo` is missing or has no value after it, and that case falls into "motivo no válido". There is no crash and no partial cancel.
- Test names describe behavior. Each assertion uses the literal text from the spec, and the invalid-reason text is hoisted into `invalidReason`.

#### Minor (Nice to Have)
