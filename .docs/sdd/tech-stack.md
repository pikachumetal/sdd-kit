# Tech Stack — sdd-kit

- **Contenido**: Markdown puro (SKILL.md con frontmatter YAML según la spec de agentskills.io + plantillas + evidencia de tests). Sin código ejecutable, sin build, sin CI (por ahora).
- **Distribución dual**:
  - Plugin de Claude Code: `.claude-plugin/plugin.json` (manifest, versión SemVer) + `.claude-plugin/marketplace.json` (source: `.`). Instalación: `/plugin marketplace add <ruta-o-repo>` + `/plugin install sdd-kit@sdd-kit`. Las skills quedan namespaced `sdd-kit:<skill>`.
  - CLI de agent skills: `npx skills add <org>/sdd-kit [-a claude-code] [--skill <nombre>]` — escanea `skills/<nombre>/SKILL.md` e instala la carpeta completa (auxiliares incluidos).
- **Dependencias**: declaradas en el [README](../../README.md#dependencias), que es la fuente única — `superpowers` (obligatoria, resuelta por `plugin.json` contra el marketplace `claude-plugins-official`) y `grilling` (opcional, `npx skills add`). Aquí no se repite la lista: dos copias divergen, y de hecho lo hicieron — este documento listaba 6 skills invocadas y el README 4 (aprendizaje de la task dependencias-declaradas, 2026-09-02).
- **Tests**: subagentes (Sonnet) sobre fixtures desechables ("Acme Orders", "TimeTrack") en el scratchpad de sesión. Sin framework: la evidencia es narrativa verificada en disco (`tests/*.md`). Orquestación de los runs con workflows multi-agente: rutas absolutas incrustadas en el script (los `args` llegan serializados), fixtures con git local propio, una copia de fixture por run, y verificación en disco además del autoinforme del agente; operaciones git de subagentes con `cd` explícito (su cwd de PowerShell no persiste). El **molde de la fixture NO lleva `.git`**: el `git init` + ramas + worktree se crean EN la copia por run — un molde con git ya inicializado rompe el `git init`/`worktree add` del setup ("already exists") y contamina el baseline (aprendizaje de la task carril-rama-worktree, 2026-07-22). El prompt/schema del baseline RED debe ser **neutro**: telegrafiar la conducta correcta (p. ej. pedir «qué leíste antes de responder») contamina el baseline y oculta el fallo — la conducta se infiere del log de acciones y se verifica en disco. Un baseline que **no falla** es evidencia válida de que la guidance sobra (Art. I): puede recortar el alcance de la task, no es un contratiempo — y un baseline limpio **en lo que buscabas** puede destapar un fallo mejor: en la task modo-lite el fallo previsto no apareció, pero sí otro que justificaba la misma solución con más fundamento. La **entrega de la skill al subagente va por prompt**, pegando el `SKILL.md` del working tree: el plugin instalado resuelve a una copia en cache (`installPath` de la versión publicada), así que un run que dependa del harness prueba la versión vieja. **Preguntar al subagente *a posteriori*** —tras cerrar el escenario, sin posibilidad de contaminar la conducta ya ejecutada— es método válido para lo que el autoinforme no cuenta: así se supo que 2/2 agentes habían omitido `brainstorming`, dato sin el cual el RED se habría cerrado con la conclusión contraria (aprendizajes de la task modo-lite, 2026-09-02).
- **Git**: rama única `master` por ahora; sin remoto configurado (pendiente — ver roadmap).
