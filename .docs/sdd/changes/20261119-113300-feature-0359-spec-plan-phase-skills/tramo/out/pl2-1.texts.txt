#### Minor (Nice to Have)
1. `test/cancel.test.js:93-131` · The tests share the module's in-memory `bookings` state and depend on file order, which is fragile. The first test (`canceladas sin cancelaciones`) only passes if it runs before any cancellation. `canceladas enseña el motivo` and the last test only pass if `cancelar una reserva activa` ran just before them. Running a single test with `--test-name-pattern` fails, and so does reordering or inserting a test. node:test runs the tests in one file in order, and each file in its own process, so the current suite is green. The cost shows up when someone adds a test. If the plan accepted this deliberately, a cheap mitigation is to put the dependent tests in one `test` with named steps, or to export a reset helper for the test only. Keep the dependency visible in the test names: `canceladas enseña el motivo` doesn't say it needs the previous test.
2. `src/app.js:61-64` · Possible mixed levels of abstraction in `run` (Clean Code). `run` is a one-line-per-command dispatcher, and now `cancelar` carries inline flag parsing with `indexOf` and `at + 1`. Extract something like `reasonFrom(params)` so `cancelar` goes back to one line. The parsing also assumes `--motivo` comes after the positional arguments. `cancelar --motivo otro Norte lun` takes `--motivo` as the room and returns `sin reserva --motivo otro` after the reason check fails. The spec doesn't ask for any other order, so this is only a note.
3. `test/cancel.test.js:113-131` · Coverage gaps. Only `sala ocupada` is tested as a valid reason, not `cambio de planes` or `otro`. `cancelledBookings` has no test with two or more cancellations, so the `join('\n')` and the output order aren't exercised. A parametrised test over `CANCEL_REASONS`, or a second booking, would cover both.
4. `test/cancel.test.js` (whole file) · The file went from CRLF to LF line endings, so the diff shows every line as changed. Besides the intended assertion changes in the two original tests, this adds noise to history and to `git blame`. Check whether the project formatter requires LF. If it does, leave it. If not, restore CRLF so the real diff is visible.
