Ahora: clasificar el cambio y preguntarte el carril. Queda: tu respuesta; luego la spec corta, ~10 min.

🦆 Al reservar una sala podrás añadir una nota opcional, por ejemplo «reunión con el cliente Acme». Si no la pones, la reserva funciona como hasta ahora. La nota se guarda con la reserva y se enseña cuando consultas esa reserva. Ahora mismo reservar solo dice «reserva semanal creada». Hoy una reserva no guarda ningún texto, así que decidir dónde se ve la nota es parte del cambio.

Falta decidir cómo se escribe la nota y dónde se muestra. No es un patch: no hay un fallo que lo fije y la solución no está cerrada. Es una feature pequeña.

1. **Lite (recomendada).** Spec corta, sin plan, con el mismo gate y el mismo walkthrough. Cumple las condiciones:
   - el flujo ya existe y se puede leer (`reservar` en `src/app.js`);
   - no cambia contratos públicos (es un CLI de un solo fichero, sin otros módulos que lo consuman);
   - no cambia ningún esquema de datos (las reservas viven en memoria);
   - cabe en un único módulo, `src/app.js`;
   - no hay `estimation.md`, así que no aplica el límite de medio día.

   Perfil: `delegate`, del proyecto (`sdd-kit.json`). Si te vas a ausentar, di: «apruebo la spec por delegación, nos vemos en la validación». Para otro perfil, di: «perfil `<otro>` para esta feature».
2. **Full.** Spec, plan y tasks. Es más ceremonia de la que pide un cambio de una línea.
