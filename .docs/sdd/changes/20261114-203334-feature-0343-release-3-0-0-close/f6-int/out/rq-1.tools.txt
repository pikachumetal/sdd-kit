❓ **¿Dónde se guardan las reservas?**
1️⃣ **Un fichero JSON** (por ejemplo `reservas.json`). Se lee al arrancar y se escribe tras cada cambio. No añade dependencias, se puede abrir y editar a mano y es fácil de testear con un fichero temporal. Su coste es que dos comandos simultáneos podrían pisarse, y que una escritura cortada a medias puede dejar el fichero corrupto, salvo que se escriba a un temporal y se renombre.
2️⃣ **SQLite**, con `node:sqlite` o con una dependencia. Da transacciones y consultas, y no sufre con las escrituras concurrentes. Su coste es una dependencia o una versión mínima de Node, y un binario que no se puede editar a mano. Es demasiado para un puñado de reservas de una sola persona.
3️⃣ **Un servidor o servicio externo**. Cambia la CLI por un cliente de ese servicio. Su coste es operar algo más, para un único usuario.

➡️ **Recomiendo 1️⃣**, porque eres el único usuario y no hay concurrencia real. El volumen es de unas pocas reservas por semana y el proyecto no tiene dependencias. A cambio, si algún día hay varios usuarios o escrituras simultáneas, habría que migrar a 2️⃣.

Escena de 1️⃣: `reservar Sur lun 10:00-12:00` guarda la reserva en el JSON. Después de reiniciar el servidor, `libres 10:00-12:00` responde `Norte`, porque Sur sigue reservada.
