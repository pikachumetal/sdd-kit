# Spec review: feature 0021, «Anular con motivo y sin correo» (`e3f8cff`)

**Not ready to merge.** The review focus line works in the code but has no test, the email the spec removes is still sent, `anular-todas` doesn't ask for a reason, and the commit adds a file write and a `libres` change that nobody asked for.

I read the whole package (96 lines), the spec, the plan, the existing tests, ADR 0003 and the capability files for `bookings` and `availability`.

### Strengths
- `voidBooking` checks for the reason before anything else (`src/app.js:30`), so a void without a reason never changes a booking. The reply text is exactly the one in decision ✋1 («falta el motivo»).
- `reasonOf` (`src/app.js:20-23`) also handles `--motivo` with nothing after it: it returns `undefined`, and the command answers «falta el motivo».
- The reason is stored on the booking (`booking.reason = reason`), as the spec's Approach asks.
- The first THEN («anulada Norte lun (avería)») has a real test through `run` in `test/void.test.js:8-10`.

### Issues

#### Critical (Must Fix)

1. **The email on void is still sent.** `src/app.js:35`
   - **What's wrong:** `voidBooking` still calls `notifyByMail(\`anulada ${room} ${day}\`)`, and `notifyByMail` and `outbox` are still in the code (`:16`).
   - **Why it matters:** the spec has «REMOVED — Las anulaciones se avisan por correo», and the dev-lead decided «El correo de anulación desaparece».
   - **Fix:** remove the call (and `notifyByMail`/`outbox` if nothing else uses them). Add a test that `outbox` stays empty after `anular … --motivo …`.
   - **Gap:** `contradicts`. **Source:** the REMOVED requirement and that dev-lead decision.

2. **Saving to disk was not asked for, and it crashes the CLI on a fresh clone.** `src/app.js:1,25-27,36`
   - **What's wrong:** `saveVoided()` writes `data/anuladas.json`. `data/` is in `.gitignore`, so a fresh clone doesn't have it. There, `node src/app.js anular Norte lun --motivo avería` throws ENOENT after the booking is already marked voided, and the user never sees «anulada …».
   - **Why the test misses it:** `test/void.test.js:6` runs `mkdirSync('data')` before the test, so the test passes.
   - **Why it matters:** the spec's Scope says «No entra: guardar las anulaciones (ADR 0003…)». ADR 0003 (accepted) has the Confirmación «`src/` no importa `node:fs`», and this commit breaks it. Its `rutas: docs/**` doesn't match `src/`, which is probably why the brief listed no covering ADRs. That glob looks wrong and should be fixed.
   - **Fix:** remove `saveVoided`, the `node:fs` import and the `mkdirSync` in the test.
   - **Gap:** `unrequested`. **Source:** the spec's Scope and ADR 0003.
