## Spec review: `5fcf3a2` (feature 0025, anular sin aviso por correo)

I read the whole package in one pass (61 lines). I also read the spec, the plan, ADR 0003, the capabilities, `src/app.js` at HEAD and the three test files.

### Strengths
- The commit is small and stays in scope. `anular-todas` (`src/app.js:22-26`) is untouched, as the spec's «No entra» line asks.
- The decision «`anular` sigue respondiendo "anulada <sala> <día>"» is kept (`src/app.js:19`). `test/void.test.js:5-7` pins it through the `anular` command, which is the route that «Dónde se prueba» names.
- The dead `formatMail` helper was removed instead of being left behind.
- The new UI text is in Spanish and there are no comments, so both code constraints are met.

### Issues

#### Critical (Must Fix)

**1. The removed notice still runs: `anular` still queues a message to the responsable.** `src/app.js:18`
- **What's wrong:** `voidBooking` still runs `outbox.push({ to: 'responsable', body: \`anulada ${room} ${day}\` })`. The commit only removed the mail wrapper (the `subject` and the «(enviado por correo)» suffix). The notice is still built, still addressed to the responsable, and still comes out of the outbox: after `anular Norte lun`, `salida` prints `responsable: anulada Norte lun`.
- **Why it matters:** The delta says «REMOVED — Avisar por correo», and the Intent says «Se quita el aviso». A REMOVED behavior that still runs is a direct contradiction. Anyone using `salida` after the merge still sees the notice the dev-lead asked to remove.
- **How to fix:** Delete the `outbox.push(...)` line from `voidBooking`.
- **Gap:** `contradicts`.
- **Source:** the REMOVED requirement «Avisar por correo», and the dev-lead's decision «El aviso por correo al anular desaparece».

#### Important (Should Fix)

**2. The dev-lead's decision is only half covered.** `src/app.js:18`
- «decisión del dev-lead cubierta a medias: El aviso por correo al anular desaparece — la regla quita solo el formato de correo (asunto y sufijo) y deja el aviso al responsable en `outbox`, visible en `salida`.»
- **Gap:** `partial`.
- **Source:** «Decisiones tomadas con el dev-lead».

**3. The test named «sin aviso» never checks that there is no notice.** `test/void.test.js:5-7`
- **What's wrong:** The test only checks the response text. It passes against this commit even though the notice is still queued, so it would not catch issue 1.
- **Why it matters:** The «Dónde se prueba» line «Anular sin aviso» has no test that actually pins the «sin aviso» part.
- **How to fix:** In the same test or a new one, run `anular Norte lun` and then assert that `run('salida', [])` does not contain `anulada Norte lun`, or that `outbox` is empty. The current assertion could not have failed for the reason the test is named after.
- **Gap:** `partial`.
- **Source:** the «Dónde se prueba» line «Anular sin aviso».

- **What's wrong:** `.docs/sdd/capabilities/bookings.md` has only the requirement «Anular una reserva». There is no requirement called «Avisar por correo» for the delta to remove.
- **Why it matters:** At archive time the delta has nothing to merge against. The capability's Purpose line («y lo que se avisa al hacerlo») may also need rewording.
- **How to fix:** Confirm with the spec author how the delta should be merged.
