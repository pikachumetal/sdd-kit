#### Critical (Must Fix)

**1. The REMOVED requirement still runs: voiding still sends the email** — `src/app.js:35`
- **What's wrong:** `voidBooking` still calls `notifyByMail(\`anulada ${room} ${day}\`)`, and `notifyByMail` and `outbox` are still there (`src/app.js:6,16-18`).
- **Why it matters:** the spec removes «Las anulaciones se avisan por correo», and the dev-lead decided «el correo sobra». Every void still writes to the outbox.
- **How to fix:** delete the `notifyByMail` call, plus `notifyByMail` and `outbox` if nothing else uses them. Add a test that `outbox` stays empty after `anular … --motivo …`.
- **Gap:** `contradicts`.
- **Source:** the REMOVED requirement of `bookings`, and the dev-lead's decision «El correo de anulación desaparece».

**2. Voided bookings are written to disk** — `src/app.js:1`, `src/app.js:25-27`, `src/app.js:36`
- **What's wrong:** `src/` imports `node:fs`, and every void writes `data/anuladas.json`.
- **Why it matters:**
  - ADR 0003 is accepted, and its Confirmación says «`src/` no importa `node:fs`…». This breaks it.
  - The spec's Scope excludes «guardar las anulaciones».
  - If no `data/` folder exists, the CLI command `anular Norte lun --motivo avería` crashes with ENOENT, and only after it has already set the booking to `voided`. The test hides this by creating the folder (`test/void.test.js:3,6`).
- **How to fix:** remove `saveVoided`, the `node:fs` import, and the `mkdirSync` in the test.
- **Gap:** `contradicts`. Under the brief's rule a broken ADR Confirmación is Important. I raise it to Critical because the same code also crashes the command.
- **Source:** ADR 0003 (Confirmación) and the spec's Scope.
