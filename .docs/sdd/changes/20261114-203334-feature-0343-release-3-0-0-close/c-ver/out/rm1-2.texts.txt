**1. The removed requirement «Avisar por correo» still runs** — `src/app.js:18`
- **What's wrong:** `voidBooking` still does `outbox.push({ to: 'responsable', body: \`anulada ${room} ${day}\` })`. Only the wrapper (`formatMail`, `subject`, «(enviado por correo)») was removed, not the notice itself. Running `anular Norte lun` and then `salida` still lists `responsable: anulada Norte lun` (`src/app.js:29`). The THEN of `.docs/sdd/capabilities/bookings.md:20` describes exactly this, and it is the list the office sends by email.
- **Why it matters:** The spec's whole purpose (Intent, Approach «`anular` deja de preparar el aviso») is not delivered. The responsible person keeps getting the email nobody reads.
- **How to fix:** Remove the `outbox.push` line from `voidBooking`. Then decide whether `outbox`, `pending()` and the `salida` command still have any producer; today `voidBooking` is the only one.
- **Gap:** `contradicts`
- **Comes from:** REMOVED «Avisar por correo» in the `bookings` delta. The same root cause also covers none of the dev-lead's decision: «El aviso por correo al anular desaparece: el responsable avisa en persona». The rule in the diff only changes the notice's format, so the decision is not covered at all.

#### Important (Should Fix)

- **Why it matters:** The spec's «Dónde se prueba» line («Anular sin aviso: por el comando `anular`, como `test/void.test.js`») has no real verification. A regression that brings the notice back would not be caught.
