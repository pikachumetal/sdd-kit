**Lo que he entendido** (corrígeme si no es así): un comando nuevo, p. ej. `exportar <sala>`, que saque las reservas de esa sala en CSV. Quien responsable de la sala lo abre los lunes en su hoja de cálculo para cuadrar las reservas con lo que ella o él lleva. Hoy `src/app.js` guarda cada reserva como `{ room, day, slot }` y no hay ningún comando que las liste. Es una tarea pequeña (una sola task), así que no propongo dividirla.

❓ **¿Dónde sale el CSV?**
El resto de comandos de `run()` devuelven texto que se imprime por pantalla, y los tests comparan ese texto.
1️⃣ **Por pantalla (stdout)**: `exportar Norte` imprime
```
sala,dia,franja
Norte,lun,10:00-12:00
```
y se guarda con `node src/app.js exportar Norte > norte.csv`. Encaja con los demás comandos y se prueba igual; el coste es que quien lo use tiene que redirigir a mano.
2️⃣ **A un fichero**: `exportar Norte` escribe `norte.csv` en la carpeta actual y responde `exportadas 1 reservas a norte.csv`. Es cómodo para abrirlo directamente; el coste es que escribe en disco (y puede pisar un fichero anterior) y hay que decidir nombre y ruta.
➡️ **Recomiendo 1️⃣**, porque `run()` ya devuelve el texto de cada comando y así el CSV se prueba con un `assert.equal` como los demás. A cambio, tienes que escribir el `> norte.csv` tú.
