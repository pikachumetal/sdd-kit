## Users

- **Socio del coworking**: reserva salas y se lleva sus reservas a su calendario.
- **Responsable del coworking**: mantiene la herramienta; hace de dev-lead: decide qué entra y aprueba las specs, pero no lee el código.
- **Dev**: desarrolla la herramienta.

## Product Purpose

Reservar las dos salas de reuniones del coworking desde la terminal y llevarse las reservas de un mes al calendario de cada uno (Google Calendar, Outlook) con un fichero que se importa.

## Capabilities and Constraints

- **Es**: reservar, cancelar y exportar las reservas de un mes.
-

=== RESULTADO (6 turnos, 0.1037873 $)
Here is the path of one export, the March one. The data has three confirmed reservations in March, one cancelled, and one in April.

**What happens in the code**

1. You type the export command in the terminal and name the month, for example `2026-03`. The program reads the month and starts the export.
2. The program opens the file that holds all reservations and reads every one of them: the five above.
3. It keeps only the reservations that fall in March and are not cancelled. The cancelled one (Norte, 12 March) and the April one drop out. Three remain.
4. It puts the three in date order, then by time of day. First comes Norte on 2 March, 10:00–12:00.
5. It turns each reservation into a calendar entry. The entry is titled "Sala Norte", and it has a start and an end.
6. For the start and end, it converts the time at the coworking to UTC. UTC is the reference clock that calendars use. The program treats the coworking clock as always two hours ahead of UTC. So the 10:00 start on 2 March becomes 08:00, and the 12:00 end becomes 10:00.
7. It wraps the three entries in one calendar file.
8. It creates a folder for exports if there isn't one yet. It saves the file there, named after the month.
9. The program prints the file's location in the terminal.

**What happens outside the code**

You open the folder, take the March file, and import it into Google Calendar or Outlook. The three reservations then show up in your calendar. Nothing updates later: if you book or cancel after that, you export again.

**Two things I saw in the code**

- The two-hour gap is fixed. If the coworking clock moves by an hour during the year, the times in the file will be an hour off for part of the year.
- The converted times have no "Z" at the end, the mark that says "this is UTC". A calendar may then read 08:00 as 08:00 on your own clock, not as UTC. I haven't tested this in a real calendar.

The specs mention exporting by room, but the code has no step for that yet.

**Where to look**

- Step 1, the command: `src/cli.js`
- Steps 2–9, in order: `src/export/index.js`
- Step 2, reading the reservations: `src/bookings/repository.js`
- Steps 3–4, filter and order: `src/export/filter.js`
- Steps 5–7, calendar entries and time conversion: `src/export/ics.js`
- Steps 8–9, saving the file: `src/export/writer.js`
- The file you get: `exports/2026-03.ics`
