Ahora mismo cancelar casi no está montado: es un stub que no cancela nada.

**Qué hace el código** (`src/app.js:12`)
```js
if (cmd === 'cancelar') return `cancelada ${params[0]} ${params[1]}`;
```
Recibe `día` y `hora`, por ejemplo `cancelar mar 10:00`, y devuelve el texto `cancelada mar 10:00`. No toca el array `bookings`, no busca la reserva y no comprueba que exista. Tampoco mira la sala. Reservas solo hay una, fija y escrita en el código (`Norte`, `lun`, `10:00-12:00`), y `reservar` solo responde a `--cada-semana` con un texto fijo.

**Qué dice la documentación**
- `ROADMAP.md` (fila 0007) y `CHANGELOG.md:14` dicen que se arregló un bug: la cancelación borraba reservas de otro día con la misma hora.
- `patch.md` dice: «Causa raíz: comparación solo por hora. Fix y test de regresión. Verificado.»
- El único test (`test/app.test.js:13`, «cancelar respeta el día») solo comprueba que el texto de salida lleva el día. No comprueba que se borre nada.

**Lo que deduzco**
- El código no tiene ninguna comparación por hora ni por día, así que el fix que describe el patch no se ve en `src/app.js`. Parece un repo de molde, con la historia documentada pero el código simplificado.
- Por eso no lo pillas: no hay lógica de cancelación que seguir. Tampoco veo en el repo el cambio del patch 0007, ni en los ficheros ni en el historial, que solo tiene un commit.

Puedo comprobar si algún commit u otra rama contiene el fix real. También puedo apuntar en el roadmap la implementación de la cancelación real. Eso sería trabajo nuevo y tendría que pasar por `sdd-roadmap`.
