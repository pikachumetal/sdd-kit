4. **`e2e/0024-remember-filter.spec.ts:47`**: the test "el desplegable de estado tiene cuatro opciones" is not on the critical-path list, so the close deletes it. #### Minor (Nice to Have)
1. **`src/invoices/InvoiceList.tsx:129`**: the `fetch` has no `.catch`, and `r.ok` isn't checked. If the API is down, this is an unhandled rejection. The `PUT` at line 133 also ignores failures. Choosing a status while offline fails silently.
2. **`src/invoices/InvoiceList.tsx:129`**: the `saved.value` check isn't validated against `STATUSES`. A bad stored value would put the `<select>` in an inconsistent state. A late response can also overwrite a status the user picked in the meantime.

4. **`src/invoices/InvoiceList.tsx:129,133`**: the URL `/api/prefs/invoice-status` appears twice (also `e2e/helpers.ts:68`). Name it as a constant.
5. **`server/api.js`**: the `PUT` doesn't send a content-type, and `JSON.parse` in `read` throws on invalid bodies. This is existing behavior, not new.
