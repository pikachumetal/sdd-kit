### Issues

#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **`playwright.config.ts:7-8`: timeouts raised above the declared values.**
   - The diff adds `timeout: 90_000` and `expect: { timeout: 20_000 }`. «Project E2E» declares timeouts «por defecto», and no reason is written in `operations.md` (the diff doesn't touch it).
   - Raised timeouts hide slow or flaky behaviour in the suite for every test.
   - Fix: remove both lines, or document the reason in `operations.md`.

2. **`e2e/0024-remember-filter.spec.ts:7`: wait on internal state between two user actions, with no comment.**
   - `expect.poll(() => savedStatus(request))` polls the API after the select and before the navigation.
   - Without the poll, the app might not have saved the preference yet. That is the failure the test exists to catch, so it is not a justification.
   - Fix: delete the poll and the `savedStatus` helper (`e2e/helpers.ts:68-71`). Let the final `toHaveValue('cobrada')` assertion fail if the save was lost. If the save genuinely needs awaiting, make that a UI-visible step and comment why.

3. **`.docs/sdd/steering/critical-path.md:8`: the diff edits the critical-path list.**
   - The rule says any change to this file is a finding, because only a person edits it. The row was added by the commit `docs(testing): el filtro recordado entra en el camino crítico`.
   - Fix: revert the row and leave it for a person to add.

#### Minor (Nice to Have)
4. **`src/invoices/InvoiceList.tsx:11,16`: no error handling on the two `fetch` calls, and the saved value isn't validated.**
   - The GET has no `.catch` and the PUT result is ignored.
   - `saved.value && setStatus(...)` accepts any string, so a stale or invalid stored value gives a `<select>` with no matching option.
   - Fix: check the value against `STATUSES` and catch the errors.

5. **`src/invoices/InvoiceList.tsx:10-12`: possible race.**
   - If the user picks a status before the GET resolves, the late response overwrites their choice.
   - Fix: ignore the response if the user has already chosen, or add a cancelled flag in the effect cleanup.

6. **`server/api.js:19-21`: preferences are global rather than per user.**
   - The existing clipboard and cells code reads `x-user`, but `prefs` is keyed only by name. Every user shares one filter.
   - Neither the client nor `savedStatus` sends `x-user`.
   - Fix: key `prefs` by user, as the clipboard does. This is a judgement call, because the spec may intend a global preference.

7. **`src/invoices/InvoiceList.tsx:13-16` (Clean Code, "can you understand each function without reading its body?"): possible test gap.**
   - `InvoiceList.test.tsx` has no test for loading or saving the preference. `fetch` isn't mocked there either, so the new effect runs against a real `fetch` in that test.
   - Fix: add a unit test with a mocked `fetch`.
